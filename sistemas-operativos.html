Conocer los sistemas operativos es importante

  • Juan Pablo Hernández García
  • Científico de datos

La funcionalidad de una computadora para ciencia de datos puede variar según los sistemas operativos utilizados por las empresas. Dependiendo del entorno, se pueden implementar diferentes soluciones técnicas y herramientas para el análisis de datos. Esto significa que la capacidad de trabajar con ciertos sistemas operativos puede influir en la elección de las herramientas y bases de datos adecuadas para un proyecto determinado.

3 Entornos virtuales

Cada proyecto necesita sus propias versiones de librerías. Un entorno virtual las aísla para que un proyecto no rompa a otro y para que cualquiera pueda reproducir tu análisis.

# Crear y activar un entorno
python -m venv .venv
source .venv/bin/activate        # Linux / macOS
.venv\Scripts\activate           # Windows

# Instalar y congelar dependencias
pip install pandas scikit-learn
pip freeze > requirements.txt

Con Conda (Anaconda) se hace lo mismo con conda create -n proyecto python=3.11 y conda activate proyecto.

4 WSL: Linux dentro de Windows

Windows Subsystem for Linux permite usar una distribución de Linux (como Ubuntu) sin dejar Windows. Es la forma más cómoda de trabajar con herramientas pensadas para Linux en una computadora de empresa.

# En PowerShell como administrador
wsl --install

5 Contenedores con Docker

Un contenedor empaqueta el código, las librerías y el sistema que necesita. Así un modelo funciona igual en tu laptop, en el servidor y en la nube, sin el clásico “en mi máquina sí funciona”.

# Dockerfile mínimo para una API de un modelo
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "app.py"]

6 Servidores y nube

Servidores Linux

Donde corren las bases de datos, los procesos programados y los modelos en producción.

Nube

Azure, AWS o Google Cloud ofrecen máquinas virtuales con Windows o Linux bajo demanda (ver la página de Azure).

Tareas programadas

cron en Linux y el Programador de tareas en Windows ejecutan reportes y modelos automáticamente.

7 Buenas prácticas

  • Usar rutas relativas en el código, nunca rutas de tu computadora.
  • Evitar espacios y acentos en nombres de archivos y carpetas.
  • Un entorno virtual y un requirements.txt por proyecto.
  • Guardar contraseñas y llaves en variables de entorno, no en el código.
  • Versionar el código con Git.
  • Probar en Linux lo que va a correr en un servidor.
